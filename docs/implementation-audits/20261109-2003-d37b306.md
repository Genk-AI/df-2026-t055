# 修正履歴の保存順と直近20件の監査

- 対象は #137、基点 `d37b306`。実装・検証 Codex、独立レビュー未実施。レビューの2点を修正する。
- 同じ所属・本人・作業の履歴に連番を付け、カウンタと履歴を同じトランザクションに保存する。別の下書き・インスタンスからの同時保存も同じカウンタを競合させ、日時やランダムUUIDの順序に依存しない。連番は内部用で職員向けDTOには含めない。
- 保存順の新しい履歴20件を先に選び、その範囲内で同一工程・項目の古い修正を除く。重複で20件未満になっても21件目以前を補わない。
- 連番のない既存履歴は保存日時を使用。同時刻で同じ下書きのrevisionが異なる場合はrevisionで順序を決め、それでも順序が不明な場合は生成受付を409で拒否する。既存履歴の異なる時刻の実際のコミット順は証明できないため、実データの移行時は担当者の確認が必要。新旧バージョンが同時に履歴を書き込む運用は順序を保証できないため、切替時は旧バージョンの書き込みを止める。
- 同一時刻・UUID逆順、複数下書きの並行保存、直近20件、曖昧な旧データ、履歴保存失敗時のカウンタ巻き戻しをテスト。実Firestore上の競合・旧データ移行は未検証。後続PRは旧ヘッドをベースとしているため、この修正を取り込んだ統合確認が必要。
