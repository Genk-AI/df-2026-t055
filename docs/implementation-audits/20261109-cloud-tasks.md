# Cloud Tasks 配送の実装監査

- 対象: #47。先行する #42、#28 の変更とCloud Storage接続PRに依存する。
- 認証: generatorはGoogle署名・audience・検証済みメールとサービスアカウントを確認し、タスク実行と復旧の呼出元を分離。クラウドキュー選択時はAPIのローカル内部トークン経路を無効にする。
- 回復: 永続化後の投入失敗、配送失敗・リース期限切れ、配送回数切れは外部Schedulerによる再投入で回復する。タスク名は5分単位で冪等化し、リース中の配送は再試行させる。既存のトランザクションとリーストークンで二重完了を防ぐ。
- モックによるOIDC呼出元の分離、配送期限・ペイロード、投入失敗、回復対象、現行リースの再試行を確認。全テスト・ビルド・型検査を実行。
- 未検証: GCP上のOIDC、Cloud Tasks、Cloud Scheduler、Cloud Run、Firestore、Storage、Vertexの結合。並列1と最大試行3はキューの実設定が必要。Scheduler停止時は回復しない。本番APIの起動ガードは維持。
- 先行PR由来の依存関係のnpm audit中程度4件が残る。
