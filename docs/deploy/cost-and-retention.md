# 生成受付・費用・保管期限

## 生成受付

同じ組織のFirestoreコレクション `operations` の `generation-control` 文書に、`id: "generation-control"`、対象 `orgId`、作成時刻のISO文字列 `createdAt`、真偽値 `enabled` を保存する。`enabled: false` で新しい手順生成受付を停止し、`true` で再開する。文書がない場合は受付を許可し、値が真偽値の `true` 以外なら停止する。文書の書き換えは基盤担当の権限に限定し、通常利用者に直接の書き込み権限を与えない。受付と設定の読み取りは同一Firestoreトランザクション内で行う。受付済みジョブの中断機能ではない。

停止後は新規生成が `GENERATION_PAUSED` を返すこと、既存の編集・承認版閲覧・本人支援が継続することを確認する。操作前後の時刻、担当、対象プロジェクト・組織、確認結果を記録する。`GENERATION_GLOBAL_LIMIT` と作業ごとの10回上限も引き続き有効。修正履歴の参考メモ用ジョブは別PRの実装時にも同じ制御を適用する。

## 予算と実行環境

基盤担当は請求先アカウントの予算20ドルに対して実費5・10・15ドル相当の通知を設定し、各通知先と受信を確認する。予算通知は強制停止ではなく遅延し得る。15ドル通知時は上記の手順で受付を停止する。Cloud Runは最小0、web最大2・generator最大1、Cloud Tasksは並列1・最大試行3とする。既存ジョブとWebSocketも費用を消費するため、通知と別に請求画面・キュー滞留を確認する。これらの設定は本PRではクラウドへ適用していない。

## ログと削除

アプリ実装ではプロンプト本文、動画、プロフィール、支援記録、修正履歴、認証トークンを出力しない。Cloud Runやプロキシのリクエストログ、例外・外部SDKログ、監視のエクスポート先にも同じ情報が入っていないか、テストデータで閲覧権限を持つ担当が確認する。認証ヘッダーや本文を記録する設定を有効にしない。実環境のログ確認は未実施。

11/14まではデモと提出URLを維持し、11/15以降に担当が対象環境・対象組織を確認してデモ用の素材、プロフィール、操作履歴、支援記録、修正履歴、参考メモ、生成入力スナップショットを削除する。未参照のアップロード・生成途中資産は、停止した処理がないことと承認版等から参照されていないことを確認してから対象を確定する。コレクションやバケットの一括削除を自動実行しない。バックアップ・ログ・保存先の保持設定と削除権限を含めて対象一覧、実行者、時刻、件数、削除後の確認結果を記録する。共有データや提出物を誤って消さないよう、削除対象の最終確認は実環境の担当者が行う。
