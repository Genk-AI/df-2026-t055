# 架空プロフィールと本人役のシナリオ

**すべて架空のデモ設定です。実在する本人の希望・観察記録ではありません。** [正本第0〜4節](../PRODUCT_SPEC.md) の2つの表示方法を、同じタオル作業で確認する素材として使います。所属先、障害名、読みの能力から表示方法を決めません。

これは登録画面への入力案です。APIリクエストやseedデータのスキーマは定義せず、認証アカウントの作成・紐づけは別の管理手順で行います。

## 登録する内容の案

| 項目 | デモ利用者A | デモ利用者B |
| --- | --- | --- |
| 表示名 | デモ利用者A | デモ利用者B |
| 表示方法 | 写真のみ（`photo_only`） | 写真と短文（`photo_text`） |
| 読み上げ | 利用しない（`audioGuidance: false`） | 利用しない（`audioGuidance: false`） |
| 本人の希望として演じる内容 | 写真を見て作業したい | 写真と短い文を一緒に見たい |
| 職員が観察した事実 | 未観察。練習後、実際に見た動作だけを記録する | 未観察。練習後、実際に見た動作だけを記録する |
| 職員の提案 | 写真の順序と、文字で出さない注意の伝え方を対面で確かめる | 工程文の言葉と写真が、実物の動作に結びつくか確かめる |
| 確認済みの説明上の配慮 | 未確認 | 未確認 |
| 文の長さ・区切り等の未確認項目 | 未確認のまま省略する | 未確認のまま省略する |
| 障害に関する任意情報 | 記録しない | 記録しない |

読み上げを使うデモは、希望の確認と承認済み音声の用意ができた後に追加します。未承認文の音声生成や、実行時の音声生成を前提にしません。

## 本人役のシナリオ

以下はチーム内で演じる場面です。両者の能力差や、実際の利用者への適合性を示すものではありません。画面の実装・承認・割当が済んでいることを担当者が確認してから使います。

| 場面 | 本人役の操作 | 確認担当が見ること |
| --- | --- | --- |
| 開始 | 割り当てられたタオル作業の「はじめる」を押す | 承認版で1工程が開く。Aは写真のみ、Bは写真と工程文。表示方法にかかわらず操作名と状態は残る |
| 前後の移動 | 「つぎへ」で進み、「もどる」で前の写真を見る | どこへ移るか分かるか。「もどる」は実物の折りや封を取り消す操作ではないことも確かめる |
| 援助の練習 | 袋に入れる場面で「手伝って」を押す | 送信中・受付後の待機・担当決定を区別する。職員が実物の袋口を広げる手本を示す |
| 支援後 | 職員は希望を確かめて「対応を終えてつづける」、または対応完了後に本人役が「つづける」を押す | 同じ工程・同じ版へ戻る。支援記録の入力やAI処理の完了を再開条件にしない |
| 停止 | 本人役が「やめる」を押す | 確認待ちを挟まず手順と進行ボタンが閉じる。停止したセッションは再開しない |

援助を求める場面は練習の設定として伝え、失敗するように仕向けません。「手伝って」を使ったこと自体を失敗と数えず、迷った箇所、援助の内容、本人役の言葉、観察者の解釈を分けて記録します。

通信断・古い通知・停止優先の技術検証は [#81](https://github.com/Genk-AI/df-2026-t055/issues/81)、表示とピクトグラムの確認は [#82](https://github.com/Genk-AI/df-2026-t055/issues/82) の範囲です。このシナリオを用意しただけでは、それらを検証済みとしません。

## 実際の本人と確認するとき

チームの本人役と、実際の利用者による評価は記録を分けます。実際の本人が参加する場合は [正本第8節](../PRODUCT_SPEC.md#8-検証とデモの合格条件) に従い、参加内容・記録する内容・休憩や中止を選べることを本人に分かる方法で説明します。録画は別に確認し、誰に同席してほしいか、どのように伝えたいかも確かめます。

写真が何を表すか、どの工程をひとまとまりにするか、文字や音声を希望するか、援助・停止の意味が伝わるかは本人と現場で確認する事項です。ここにある架空の希望を、実際の本人の希望として転記しません。
